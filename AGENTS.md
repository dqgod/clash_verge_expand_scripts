# Repository Guidelines

## Project Overview

This repository contains a Clash Verge Rev global extension script. The main file is `extension-script.js`, which transforms a Clash config at load time by:

- Creating regional `url-test` proxy groups from proxy names.
- Creating service `select` proxy groups from `SITE_CONFIG`.
- Creating `rule-providers` and prepending `RULE-SET` rules for those services.

`config.yaml` is a managed subscription config and should not be edited for normal feature work.

## Important Files

- `extension-script.js`: Core Clash Verge extension script and optional Node self-update entrypoint.
- `config.yaml`: Managed Clash config used for local verification.
- `package.json` / `package-lock.json`: Node dependencies for local testing and self-update.
- `CLAUDE.md`: Older project notes; verify against current `extension-script.js` before following any workflow there.

Do not commit `node_modules/`.

## QuickJS Compatibility

Clash Verge runs the extension in a QuickJS-like sandbox. Keep the runtime path compatible:

- `main(config, profileName)` must be synchronous and return the config object.
- Do not require Node APIs in the Clash runtime path.
- Keep Node-only code guarded by:
  ```js
  if (typeof require !== 'undefined' && typeof module !== 'undefined' && require.main === module) {
  }
  ```
- Prefer `var`, traditional `for` loops, `indexOf`, and `Object.keys`.
- Avoid arrow functions, `for...of`, `Set`, `Map`, spread syntax, and top-level async behavior in code used by `main()`.

`module.exports` is allowed only for local Node tests and must stay behind the existing `typeof module !== 'undefined'` guard.

## Service Rules

Add services only by editing `SITE_CONFIG` in `extension-script.js`.

Supported forms:

```js
'https://example.com/RulesetName.list'
{ url: 'https://example.com/RulesetName.list', icon: '🌐' }
```

The service name is inferred from the `.list` filename unless `name` is explicitly provided. Clash runtime no longer depends on `DOMAIN_CACHE`; it creates `rule-providers` directly from `SITE_CONFIG`, and the Clash/Mihomo core fetches the remote rules.

`DOMAIN_CACHE` is only a fallback/self-update cache generated by `node extension-script.js`. Do not hand-edit it unless deliberately repairing generated output.

## Expected Behavior

For each active `SITE_CONFIG` entry, `main()` should:

- Create a service proxy group named `<icon> <serviceName>`.
- Create or update a provider named `site-<normalized-service-name>`.
- Prepend `RULE-SET,<providerName>,<serviceGroupName>` to `config.rules`.
- Avoid duplicate groups and duplicate rules across repeated calls.

Regional groups should still be inserted into `🚀 节点选择`; service groups must not be inserted there, to avoid circular dependencies.

## Verification

Run syntax check:

```bash
node --check extension-script.js
```

Run a behavior check against the managed config:

```bash
node -e "const yaml=require('js-yaml');const fs=require('fs');const {main}=require('./extension-script.js');const config=yaml.load(fs.readFileSync('./config.yaml','utf8'));const out=main(JSON.parse(JSON.stringify(config)));console.log(Object.keys(out['rule-providers']||{}).filter(k=>k.startsWith('site-')));console.log((out.rules||[]).filter(r=>String(r).startsWith('RULE-SET,site-')).slice(0,10));"
```

If the sandbox blocks Node with `EPERM` on Windows paths, rerun the same command with the approved elevated Node permission rather than changing the code.

Optional cache refresh:

```bash
node extension-script.js
```

This may use the proxy configured in `C:\Users\dangqi\scripts\proxy\proxy.conf`.

## Editing Rules

- Keep edits scoped to `extension-script.js` unless documentation or package metadata truly needs updating.
- Preserve the single-file extension model; do not split runtime code into modules because Clash Verge consumes the script file directly.
- Do not edit `config.yaml` for feature implementation.
- Do not add generated dependency folders to git.
